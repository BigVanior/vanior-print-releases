# Архив: интеграция Bambu Studio — контракт v1.1

> Контракт не используется и не поставляется в релизе VANIOR PRINT 0.6.6.
> Документ сохранён только для истории миграции на самостоятельный VANIOR Slice.

Дата проверки: 2026-08-23. Проверенная версия: Bambu Studio `02.08.02.61`.

## Контракт

Адаптер запускает официальный локальный CLI со следующими принципами:

- `--datadir` всегда указывает на новый каталог внутри результата;
- `--outputdir` никогда не совпадает с каталогом исходной модели;
- используется одна явно выбранная plate, по умолчанию первая;
- существующий выходной каталог не принимается;
- исходный STL/3MF и шаблон проверяются SHA-256 до и после операции;
- готовый 3MF сверяется с целевой моделью по имени, треугольникам и геометрии;
- встроенный в 3MF G-code должен совпасть с отдельным G-code по SHA-256;
- глобальные пользовательские профили не записываются и не изменяются;
- `result.json` считается авторитетным результатом, а не код GUI-launcher процесса.

Последний пункт важен в Windows: GUI-subsystem executable может вернуть управление
раньше, чем завершится headless-задача. Адаптер ожидает `result.json` до заданного
таймаута и читает `return_code` из него.

## Вход 3MF

Готовый Bambu-проект содержит объединённые printer/process/filament settings.
Pipeline извлекает только печатаемые объекты выбранной plate, объединяет их в
контрольную STL-геометрию и обрабатывает её тем же путём, что и обычный STL.
Цвета и разбиение на исходные объекты при этом не сохраняются: приоритетом является
однозначная проверка фактической печатаемой геометрии.

## Вход STL

STL не содержит принтер, материал, пластину и технологический профиль. Пользователь
указывает проверенный 3MF через `--profile-template`. Адаптер создаёт новый проект,
заменяет mesh шаблона целевым STL, удаляет остальные build-items и оставляет ровно
один печатаемый объект. Так профиль наследуется без риска напечатать модель шаблона.

Шаблон следует предварительно открыть в Bambu Studio и проверить:

- Bambu Lab P1S и фактический диаметр сопла;
- PLA/PETG и конкретный профиль катушки;
- тип пластины;
- process profile;
- отсутствие ошибочных пользовательских G-code команд.

## Сравнение поддержек

`--compare-supports` проверяет три независимых стратегии:

```text
enable_support = 0
enable_support = 1; support_type = normal(auto)
enable_support = 1; support_type = tree(auto)
```

Ключи также добавляются в `different_settings_to_system`, иначе Bambu Studio может
заменить их значениями системного профиля при загрузке. Для каждого варианта
создаются отдельные `result.json`, готовый 3MF и G-code. Если вариант без supports
не имеет предупреждений, а геометрический риск LOW/MEDIUM, выбирается `none`.
При HIGH сравниваются normal/tree: 60% времени и 40% общей массы.

## Доступные метрики

- итоговое и core-время печати;
- время слайсинга и генерации supports;
- время G-code features с названием Support;
- общая масса по каждому слоту;
- model+support mass и технологический overhead;
- оценочная длина по массе, плотности и диаметру;
- стоимость по цене из 3MF;
- слой, стенки, заполнение, предупреждения и число треугольников.

Официальный `result.json` 2.8.2.61 складывает model и support в `main_used_g`.
AI Print Optimizer дополнительно разбирает маркеры `; FEATURE:` в G-code и считает только
положительную экструзию с движением X/Y. Это исключает ретракты, возвраты и
стационарную продувку. Масса вычисляется из длины, диаметра и плотности филамента.
На реальных контрольных G-code сумма всех ролей совпала с итогом слайсера в пределах
округления.

## Pipeline и манифест

`--pipeline-output` связывает извлечение 3MF, анализ, консервативный ремонт,
ориентацию, применение рекомендуемых настроек и слайсинг. В корне результата
создаются `ready-to-print.3mf`, `ready-to-print.gcode` и `manifest.json` с версией приложения, Python, путём и SHA-256
слайсера, параметрами, отчётами стадий и SHA-256 каждого входа и артефакта.

Проверка:

```bash
ai-print-optimizer path/to/manifest.json --verify-manifest
```
